# 频谱环

`--viz 1` 在封面周围画一圈径向柱子，颜色与进度环同一套单色。**默认关闭，不显式打开就不会动到
版面**（关闭时版面与功能加入之前逐字节一致，验证方式见 [internals.md](internals.md)）。

![带频谱环的卡片](card-viz-460x690.png)

`--size 460x690 --viz 1 --lyrics 4 --time 1 --album 1`，实机播放时截取，用的是默认的
`--viz-fx` 链路。环上的信号就是播放器自己的音频，从 3 点钟方向的最低频段顺时针走：右侧到
底部长出的柱是低音，顶部的短柱是几乎空的空气频段。

抓取侧、匹配规则与文中数字的实测来源，见 [internals.md](internals.md) 的「频谱环」一节。

## 用法

```bash
./pw-mpris-visualcard-native --viz 1                          # 跟随 MPRIS 里的播放器
./pw-mpris-visualcard-native --viz 1 --viz-bars 96             # 更密的环
./pw-mpris-visualcard-native --viz 1 --viz-source musicfox     # 钉死目标
./pw-mpris-visualcard-native --viz 1 --viz-fx 0                # 柱高就是实测值
```

自动匹配失败时用 `--viz-source` 指定 PipeWire 节点名或应用名。匹配不上也不静默空白：环里只留
底圈，stdout 打一行指明问题的提示。`--demo --viz 1` 会渲染一条假频谱，因此没有播放器也能调
版面。

## 它抓的是什么

1. MPRIS 告诉当前是哪个播放器在播。
2. 从 PipeWire 注册表枚举音频节点，与该名字整词匹配。
3. 把输入流指向该节点的 `object.serial`，PipeWire 就会交出它的 **monitor** 端口——也就是这个
   播放器在任何设备混音、音量、效果之前送出的信号。这条路不给音频路径加延时。
4. 2048 点 Hann 窗 FFT 折叠成对数间隔的频段，柱子向外生长。

音频进来后**什么都不做**：不加增益、不加噪声门、不做 AGC、不做平滑。抓到的本来就是播放器
自己的信号，再加一道电平处理，画出来的就不是音乐本身的频谱了。柱高来自一个**固定**的
dB 窗口（`-85..-30 dBFS`，量出来的，不是猜的），所以与实际播放量成正比，曲目之间也可比。

上面这几句都属于显示端的活儿，实际由 `--viz-fx` 那条**默认开启**的链完成，`--viz-fx 0`
可以整条关掉。

## 版面取舍

环需要整圈留白，而环的下缘正是文字开始的地方，所以开启时是把封面上方的间距撑开、同时从纵向
预算里扣掉顶部那一份，而不是让柱子长到第一行文字上或跑出画布。环与封面**反向、且慢 4 倍**
（`kVizSpinRatio`），读起来是两个独立的运动；`--spin 0` 时两者都停。

环的粗细现为 `0.052×H`（`360px` 基准下 12..30px）。改厚要重新确认版面仍然装得下，四个方向
都要算，见 [internals.md](internals.md) 的「柱子的粗细」——那里记了一个早期 bug：只算
宽度和封面上方、没人替顶部付账，结果环的最上沿被画到画布外 41px。

## 后处理链

`--viz-fx 1`（即默认）接上一条处理链，其中**柱子的运动模型直接取自
[cava](https://github.com/karlstav/cava) 的 `cavacore.c`**，常数照抄。默认开启：正是这条链
让柱子有重量；`--viz-fx 0` 把它整条拿掉，柱高就回到分析器实测到的值。

```text
gain（展开） → cava 运动模型（重力下落 + 积分动量） → 频段轴 1-2-1 模糊 → 滑动窗口自动增益
```

| 环节 | 开关 | 默认 | 作用 |
| --- | --- | --- | --- |
| 展开 | `--viz-gain DB` | `0` | 给每个频段加 dB。允许超过满格、由绘制时按柱钳位，这样各频段保住相对差距，不会在顶部被压成一条平线 |
| 重力 | `--viz-gravity N` | `77` | cava 的运动模型。**上升时**直接用实测值，零平滑；**下落时丢掉实测值**，改由本轮上升的峰值沿一条平方曲线落下来——下落中的柱子是一条合成曲线，无论音频多抖都影响不到它。再加一道积分给动量。这就是它看上去有重量的原因。`10` 及以下关闭运动模型 |
| 整形 | `--viz-shape N` | `50` | 沿频段轴的 1-2-1 模糊，让一根孤柱变成三柱的小山而不是一个孤立尖峰。边界复制，首尾两根不会被绕回去抹成一团 |
| 自动增益 | `--viz-norm MS` | `2000` | 把环整体缩放，使其在安静与响亮段落都填满自己的带宽。参考取窗口内最响的一帧并做平滑，增益不会跟瞬态抖。频段之间的相对动态完整保留——它只是一个标量 |

常用调法：

```bash
./pw-mpris-visualcard-native --viz 1 --viz-gravity 95          # 更重，落得更慢
./pw-mpris-visualcard-native --viz 1 --viz-shape 100           # 最大的小山整形
./pw-mpris-visualcard-native --viz 1 --viz-norm 0              # 关掉自动增益
```

两点需要知道：

- **没有降噪，也没有噪声门。** 抓到的已经是播放器自己的输出，里面每个起伏都是音乐；门限唯一
  能做的就是削掉音乐本体、把瞬态切掉。环拿到的是一个整体缩放，而不是「决定哪些频段有资格
  存在」。（cava 那个叫 `noise_reduction` 的旋钮其实是平滑强度，本项目改叫 `--viz-gravity`，
  免得被误解成降噪。）
- cava 的帧率补偿是单个 `pow(66/fps, 2.5)`，到 20fps 都还成立，再低就会塌——整根柱子一帧落完，
  看起来是闪断。因此运动模型单独钳了 dt，让极低的协商帧率变成「落得慢几帧」而不是「柱子闪烁」。
  这是对 cava 的一处有意偏离。

开 `--viz-fx` 时 `--dump` 会先连续渲染 12 帧再取最后一帧：运动模型与自动增益都需要历史，
第一帧的状态不代表实际画面。

**故意没做**的：cava 的圆头柱、颜色渐变、上下翻转——它们与本项目单色硬朗的基调相冲。

`--viz-fx 0` 并不是"每级都中性"的同义词：`--viz-gravity 0` 只关掉运动模型，`--viz-shape`
（默认 50）与 `--viz-norm`（默认 2000）照跑。要逐位透传就三个一起关。
